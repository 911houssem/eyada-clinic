# عيادة — نظام إدارة العيادات

نظام متكامل لإدارة العيادات والمواعيد والمرضى والفواتير، مع **صفحة حجز عامة** لكل عيادة. يعمل بسيرفر Node بدون أي اعتماديات خارجية (Zero dependencies) وواجهة عميل مبنية مسبقاً (Next.js static export).

> 📜 الرخصة: [MIT](LICENSE) — والمساهمة مفتوحة وفق [CONTRIBUTING.md](CONTRIBUTING.md) و[مدونة السلوك](CODE_OF_CONDUCT.md).

## ✨ المميزات

- **الحجز العام للمريض**: صفحة مستقلة لكل عيادة عبر رابط مخصص، مع **تخصيص الوقت تلقائياً** لأقرب موعد متاح (تسلسل المواعيد) ومنع الحجز المكرر لنفس الرقم في اليوم نفسه.
- **إغلاق الموقع مؤقتاً**: من شاشة الإعدادات يمكن لمدير العيادة إغلاق صفحة الحجز العامة (إجازة/صيانة) مع رسالة للمرضى وتاريخ عودة اختياري، فتُرفض الحجوزات الجديدة، ثم يُعاد فتحها بضغطة واحدة.
- **المواعيد**: جدول يومي/أسبوعي، إنشاء وتعديل المواعيد، حساب وقت الانتهاء حسب مدة الخدمة، وكشف التعارض.
- **الخدمات والأسعار**: تحديد **المدة (1–10000 دقيقة)** والسعر لكل خدمة، وتظهر مباشرة للمريض في صفحة الحجز.
- **المرضى والسجلات الطبية**: ملف كامل لكل مريض مع التاريخ الطبي والملفات.
- **المالية**: فواتير، ديون، بيع منتجات، وتقارير.
- **المخزون**: إدارة الأصناف والكميات وحدود إعادة الطلب.
- **الفريق والصلاحيات**: أدوار (مالك / مدير / طبيب / استقبال) مع تحكم دقيق بالصلاحيات.
- **تعدد العيادات**: إدارة عدة فروع، ولكل عيادة رابط حجز مستقل.
- **الاشتراكات والعروض**: خطط اشتراك، فترات تجريبية، وعروض/خصومات.
- **الأمان**: تغيير كلمة المرور، رمز التحقق بخطوتين (2FA)، وإنهاء الجلسات.

## 🧱 التقنية

| الجزء | الوصف |
|------|-------|
| الخادم | `server.js` — Node.js بدون مكتبات، تخزين على `data/db.json` بكتابة ذرّية |
| الواجهة | `index.html` + حزمة عميل Next.js جاهزة تحت `_next/` |
| صفحة الحجز | `booking-page.js` — ملف واحد مستقل (HTML/CSS/JS بدون خطوة بناء) |

## 🚀 التشغيل

```bash
node server.js
```

ثم افتح: <http://127.0.0.1:3000>

- لخيارات المنفذ: `node server.js --port 3001` أو `node server.js --auto-port`.
- عند أول تشغيل يُنشئ الخادم قاعدة بيانات تجريبية تلقائياً (ملف `data/db.json` غير مُضمّن في المستودع).
- فحص الصحة/الجاهزية: <http://127.0.0.1:3000/healthz> (و `/api/health` للتفاصيل، بما فيها جاهزية القراءة/الكتابة وعمر النسخة الاحتياطية).

### النسخ الاحتياطي والاستعادة

```bash
node server.js --verify-backup            # فحص أحدث نسخة (بصمة + JSON + فكّ التشفير)
node server.js --restore data/backups/db-XXXX.json   # استعادة (يرفض إن كان الخادم يعمل)
node scripts/restore.js --verify <file>   # نفس الأمر دون تشغيل الخادم
```

- كل نسخة يرافقها `<file>.sha256`؛ وبضبط `BACKUP_ENCRYPT_KEY` تُكتب مشفّرة كاملةً
  (`db-<ts>.json.enc`). الاستعادة تأخذ نسخة أمان `pre-restore-<ts>.json` أولاً.
- التفاصيل في [SECURITY.md](SECURITY.md) (قسم النسخ الاحتياطي وحدود مخزن JSON).

### حسابات التجربة

| الدور | اسم المستخدم | كلمة المرور |
|------|-------------|-------------|
| المالك (super_admin) | `admin` | `admin123` |
| طبيب | `doctor` | `doctor123` |
| استقبال | `reception` | `reception123` |

> في الإنتاج (`NODE_ENV=production`) لا تُبذر أي بيانات تجريبية ولا حسابات demo.
> أنشئ أول مالك عبر `OWNER_USERNAME` + `OWNER_PASSWORD` (12+ حرفاً) أو
> `node server.js --create-owner`. لا تُطبع أي كلمة مرور في السجل.

## 🔒 الإنتاج والأمان

الإعدادات الأمنية المطبّقة كاملة (الجلسات المجزّأة، بوابة 2FA، عزل بيانات
العيادات، رؤوس الأمان و CSRF، القائمة البيضاء للملفات الثابتة، سجل التدقيق
`data/audit.log`، النسخ الاحتياطي `data/backups/`، والتشفير الاختياري
`ENCRYPTION_KEY`) موثّقة في [SECURITY.md](SECURITY.md).

### متغيّرات البيئة

| المتغيّر | الوصف |
|---|---|
| `NODE_ENV=production` | تشديدات الإنتاج: يرفض الإقلاع بدون `ENCRYPTION_KEY`، لا بذر تجريبي، صلاحيات 700/600 |
| `DATA_DIR` | مجلد البيانات — **ضعه خارج مجلد النشر** في الإنتاج |
| `ORIGIN` | الأصل المسموح به لـ CORS (بدونه: نفس المضيف فقط) |
| `OWNER_USERNAME` + `OWNER_PASSWORD` | أول مالك في الإنتاج (12+ حرفاً) أو استخدم `--create-owner` |
| `TRUST_PROXY=1` | خلف وكيل عكسي (لضبط IP الحقيقي و`X-Forwarded-Proto`) |
| `ENCRYPTION_KEY` | **إلزامي في الإنتاج**: تشفير الحقول الطبية وسرّ TOTP على القرص (AES-256-GCM) |
| `BACKUP_ENCRYPT_KEY` | اختياري: تشفير ملفات النسخ الاحتياطي كاملةً (سرّ مستقل عن مفتاح التشفير) |
| `PORT` / `HOST` | منفذ وواجهة الاستماع |

## 🔁 نقاط API (المرحلة 2)

| النقطة | الوصف |
|---|---|
| `POST /api/auth/forgot` | طلب رابط إعادة التعيين (ردّ موحّد دائماً؛ يُرسل عبر `notifiers/`) |
| `POST /api/auth/reset` | { token, newPassword, twoFactorCode? } — يبطل كل الجلسات والأجهزة |
| `POST /api/auth/logout-all` | إنهاء كل الجلسات عدا الحالية |
| `GET /api/trash` | العناصر المحذوفة ناعماً (حسب العيادات المسموح بها) |
| `POST /api/trash/:type/:id/restore` | استعادة (صاحب العيادة/المالك) |
| `DELETE /api/trash/:type/:id` | حذف نهائي فوري |
| `GET <list>?page=&limit=&q=&sort=` | ترقيم اختياري يرجع `{items,total,page,limit}` |

- `:type` ∈ `patients | appointments | invoices | records | inventory | services | tasks`.
- **توافق خلفي**: بلا `page`/`limit` يبقى الشكل القديم كما هو، فيعمل الـ UI الحالي
  دون تغيير. لتحديث الواجهة ليستفيد من الترقيم/المهملات يلزم تعديل الحزمة المبنية
  `_next/` (بلا مصدر) — انظر قائمة «تحديثات الواجهة المطلوبة» في تقرير المرحلة.

## 🔔 نقاط API (المرحلة 3)

| النقطة | الوصف |
|---|---|
| `GET /api/notifications` | إعداد الإشعارات + آخر قائمة الإرسال + السجل (صاحب العيادة) — بلا أسرار |
| `PUT /api/notifications` | ضبط القناة/المنطقة الزمنية/ساعات الهدوء/القوالب + بيانات المزوّد |
| `POST /api/notifications/test` | إرسال رسالة اختبار وتفريغ قائمة الانتظار فوراً |
| `GET /api/public/booking/:slug/appointment?token=` | قراءة الحجز برمز الإدارة |
| `POST /api/public/booking/:slug/cancel` | { token } — إلغاء الحجز |
| `POST /api/public/booking/:slug/reschedule` | { token, date } — تأجيل الحجز |

- الإرسال غير متزامن عبر قائمة انتظار مع 3 محاولات وتراجع أُسّي وسقف معدّل لكل عيادة.
- تأكيد الحجز يعيد `manageToken` + `manageUrl` ويُدرج إشعاراً عند تفعيل القناة.
- صفحة الحجز العامة تعرض مربّع موافقة إلزامياً، وصفحة `?manage=<token>` للتأجيل/الإلغاء.

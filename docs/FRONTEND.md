# الواجهة الأمامية — الوضع والخطة

## الوضع الحالي (مؤكد بالفحص)

- مجلد `_next/static` يحتوي **10 ملفات chunks مبنية + media فقط**: لا `.map`،
  لا sourcemaps، ولا `__NEXT_DATA__` في `index.html` (تصدير ثابت قديم، سطر
  واحد مضغوط).
- **لا يوجد مصدر** (لا `pages/` ولا `app/` ولا `src/` ولا إعداد بناء) في
  المستودع. الاستعادة من المبني غير عملية.
- ما هو بمصدر مملوك: `booking-page.js` (صفحة الحجز العامة كاملة) و`index.html`
  (الغلاف). كل الميزات الجديدة تُسلَّم كـ API أولاً لهذا السبب.

## القواعد المتبعة الآن

- يُمنع تعديل `_next/` المبنية إلا للضرورة القصوى مع توثيق الـ patch.
- أي شاشة جديدة تُقترح كـ API + تُسجَّل في قائمة «تحتاج واجهة» (راجع `ROADMAP.md`).

## خطة الاستعادة/الاستبدال (تحتاج قرار المالك ⏳)

**الخيار (أ): إعادة بناء بـ Next.js/React على نفس الـ API**
- الأنسب إن أُريد الحفاظ على التصميم الحالي بدقة.
- يتطلب: توثيق الشاشات من `docs/SCREENS.md` + اللقطات كمرجع، ثم بناء
  من الصفر ضد الـ API الموثق (كل نقطة مختبرة).
- المخرج: مصدر قابل للصيانة + بناء reproducible يحل محل `_next/`.

**الخيار (ب): طبقة HTML/JS خفيفة بجانب الحزمة**
- صفحات مستقلة على غرار `booking-page.js` للميزات الجديدة فقط، والحزمة
  القديمة تبقى للشاشات الحالية.
- أسرع وأرخص، لكن بازدواجية طويلة المدى.

> لا يبدأ التنفيذ قبل اختيار المالك وتوفير مصمم/مطوّر واجهات للمراجعة
> البصرية (RTL/عربي) — راجع `ROADMAP.md`.
